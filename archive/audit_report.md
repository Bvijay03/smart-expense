# Smart Expense — Full-Stack Code Audit Report

**Stack confirmed:**
- Frontend: React Native (Expo SDK ~54, RN 0.81.5, React Navigation v7, TanStack Query v5, Zustand v5, React Hook Form v7)
- Backend: Node.js / Express v5, Prisma v7 (driver-adapter mode via `@prisma/adapter-pg`), PostgreSQL (Neon)
- Navigation: React Navigation (Native Stack + Bottom Tabs) — **not** Expo Router

---

## 1. Executive Summary

| Severity | Count |
|---|---|
| 🔴 Critical | 5 |
| 🟠 Structural | 12 |
| 🔵 Cosmetic | 7 |

**Top 5 issues that matter most:**

1. **🔴 CRITICAL — Plaintext security answers stored in the DB** (`auth.service.ts:63`, `:156`). The security answer is lowercased and compared as plain text. A DB leak exposes all answers directly.
2. **🔴 CRITICAL — Real database credentials committed to `.env`** (`backend/.env:1`). A live Neon connection string with credentials is checked into the repo.
3. **🔴 CRITICAL — `recalculate()` deletes + recreates settlements non-atomically** (`settlements.service.ts:38–56`). Two separate Prisma calls with no transaction wrapper — a crash between them leaves the group with no settlements.
4. **🔴 CRITICAL — `/recurring/process` is privilege-escalated** (`recurring.router.ts:11`). Any authenticated user can trigger batch processing of ALL users' recurring expenses.
5. **🔴 CRITICAL — Floating (unawaited) Promise in budget alert check** (`expenses.service.ts:72`, `:99`). `checkBudgetAlerts()` is called without `await`, making errors non-deterministic.

## 5. Not Flagged, But Worth Confirming

1. **Recalculate-on-every-mutation pattern** (`shared-expenses.service.ts:113`, `:136`). Settlement recalculation deletes all pending settlements and regenerates them on every shared-expense create/delete. Simple and correct for small groups. Could become a race-condition window under concurrent writes in large groups. If intentional for simplicity — fine, just confirm.

2. **`joinByCode` creates a JoinRequest, not direct membership** (`groups.service.ts:221–273`). A valid invite code puts the user in PENDING state requiring admin approval. This is confirmed intentional by the comment on line 252 ("Create join request"). Flagged in case the UX intent was "code = instant access."

3. **Security question as password recovery** (`auth.service.ts:139–168`). Beyond the hashing issue (already flagged as Critical), security-question-based recovery is inherently weak against social engineering. If this is a deliberate scope decision for the academic project, that's fine.

4. **`globalThis` Prisma singleton in an Express server** (`database/prisma.ts:6–21`). The `globalThis` pattern is designed for Next.js hot-reload. In a plain Node/Express server, production doesn't set `globalForPrisma.prisma` (blocked by `if (env.NODE_ENV !== "production")`), so a fresh client is always created at import time. The singleton is a no-op in production but harmless.

5. **Guest users with blank `passwordHash`** (`users.repository.ts:30`). The empty string `""` is not a valid bcrypt hash. If `bcrypt.compare(password, "")` is ever called on a guest account, it may throw rather than return `false` on some bcrypt implementations. Worth a defensive guard in `comparePassword`.

6. **`nodemailer` in `package.json`** (`backend/package.json:25`). Already flagged as unused. Worth confirming whether email-based notifications (password reset emails, budget alerts) were planned and abandoned — if so, the intent should be documented or the dependency removed.
